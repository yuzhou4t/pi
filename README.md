# Pi Agent

Pi Agent 是一个以长期项目为中心的本地个人工作流播放器：项目保存长期状态，工作流负责周期性推进，用户在关键判断和正式写入前审阅确认。

正式开发目录：`/Users/yuzhou4tc/Public/pi Agent`

## 当前状态

- 简体中文、轻量化 Web 原型；三栏外壳和首个可点击的 Run 纵向切片已经完成。
- 产品定位与第一个工作流已经确认；首版不建设通用工作流市场。
- 第一个闭环是「期刊追踪 → 五分钟导读 → 分阶段精读 → Zotero/Obsidian → 项目状态更新」。
- 前端可以完整走过 5 篇候选审阅、最多选择 2 篇、逐篇导读决定、四阶段精读、内联写入预览、部分失败和失败项重试。
- Run 使用版本化 `localStorage` 恢复；当前论文、来源、模型处理和外部写入仍是 fixture/计时器演示，不会读取或改动真实项目。
- 正式写入采用内联预览、逐项选择和一次批量确认；右栏不设常驻确认队列。
- 候选首屏先回答“论文讲什么”和“对项目的作用”，依据再按需展开；右栏用“当前依据 / 项目状态”切换，避免把所有次要信息同时铺开。
- 下一实现切片是本地服务、Run Store 和只读项目绑定，先替换前端演示状态，不接正式写入。

详细决策见 [PRODUCT_MEETING.md](./PRODUCT_MEETING.md)，首版实现合同见 [期刊追踪与精读规格](./docs/v1-journal-reading-workflow.md)。

## 当前开发原则

- 项目是用户侧主体，工作流是内部推进方式，Run 是一次具体执行。
- Codex 负责创造、修改和修复工作流；Pi Agent 负责低摩擦地重复播放已验证工作流。
- V1 只打磨一个真实闭环，不建设通用工作流编辑器、市场或多 Agent 系统。
- 已验证的前端按钮、状态迁移和确认层级是后续服务端实现合同；后端逐步替换 fixture，不另起一套流程。
- 保持界面简单且舒适可读；极简来自减少默认可见层级，而不是缩小字号或压缩所有内容。
- 设置采用「快捷入口 + 全部设置」两层结构。
- 确认跟随当前 Run 出现，不放在常驻右栏；没有精确预览和明确批准时不写 Zotero、Obsidian 或项目文件。
- 脚本处理收集、去重和规则过滤，AI 只处理需要语义判断的少量候选。
- 后续所有实现以正式开发目录中的版本为准。
