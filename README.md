# Pi Agent

Pi Agent 是一个以长期项目为中心的本地 Agent 工作空间：项目保存长期状态，工作流负责周期性推进，项目工作会话承载普通 Agent 任务，用户在关键判断和正式修改前审阅确认。

正式开发目录：`/Users/yuzhou4tc/Public/pi Agent`

## 当前状态

- 简体中文、桌面优先的三栏工作空间已经完成；左上先选择 `正常工作` 或 `论文精读`，两类工作分别恢复自己的项目、会话和审阅状态。
- `正常工作` 已接入真实本地纵向链路：macOS 文件夹选择与创建、服务端安全项目标签、Pi SDK 持久会话、公开计划和工具活动、只读文件、服务端重算 Diff、哈希绑定确认写回，以及保留每次尝试的有界验证记录。
- 项目工作会话以 Agent 为中栏且默认占满可用宽度，右侧按需打开 `文件 / 更改 / 预览 / 运行`。页面打开、项目或会话切换、模型切换、工件切换都不会调用模型；只有显式发送才启动 Pi，会话内 steer、abort 和 compact 使用 Pi 原生能力。
- 正常工作会话支持首条消息确定性命名、手动重命名和有确认的永久删除。删除只清理 Pi Agent 拥有的会话记录与未应用草稿；运行中的任务不会被暗中停止，绑定项目、已经确认的文件修改和 Git 历史都不会被删除或回滚。
- Agent 通过真实项目的受控只读视图和每个会话的稀疏审阅层工作；浏览器永远不接收真实绝对路径。所选修改写回前会再次核对 change-set hash 和逐文件 base/after hash，同一项目的写回串行执行并做读回校验。验证只在用户显式启动时物化一次性项目副本，不提供自由终端；界面会展示最终命令、解析到的项目脚本和当前本机权限边界。
- 第一个闭环是「周期监测 → 候选筛选 → 五分钟导读 → 用户选择的分阶段精读 → Zotero/Obsidian 归档 → 项目状态更新建议」。
- 前端 fixture 展示 5 篇候选，其中 2 篇可走完整演示闭环；真实 Run 只允许全文解析完成的候选进入逐篇决定，单轮最多选择 2 篇。
- 第一条本地模型纵向切片已经接通：浏览器通过同源 `/api` 调用回环 Node.js 服务，为候选生成“论文讲什么 / 对项目的作用”。服务商菜单现在真实对应 `GPT · Codex 订阅` 与 `DeepSeek API`。
- GPT 通道由本机官方 Codex CLI 复用 ChatGPT 登录态，不读取 OAuth 文件，也不需要 OpenAI API Key；调用时禁用工具、用户配置与规则，使用临时空目录和固定输出 schema。DeepSeek 通道只读取 `.env.local` 中独立的 `PI_DEEPSEEK_API_KEY`，支持 `deepseek-v4-pro` 与 `deepseek-v4-flash`。
- 两条通道共用字段级输入上限、应用层输出校验、同输入并发去重、按服务商/模型隔离的输入哈希缓存，以及不含论文正文和密钥的审计记录。
- 页面加载和切换服务商不会调用模型；候选区只有点击“用当前模型更新”才会产生一次真实请求。开发服务器与模型 API 都只监听本机回环地址。
- 已接入持久化 Run Store、11 个来源注册表、DBLP 两跳论文集扫描、逐来源游标、标准化/去重/主题过滤、OpenAlex 补充、经典论文兜底和 5 篇结构化初筛。只有本周发表才标为新；不足 5 篇时用经典论文补齐，旧论文首次发现则明确显示“本周补发现 · 非本周新论文”。
- 最终 5 篇候选会逐篇安全下载 PDF，并在配置后作为一个批次提交 MinerU Cloud；额度耗尽、部分上传、单篇失败和稍后续查都会保留为可恢复状态。已经解析完成的真实候选可直接在中栏切换“逐段 / 全文”，并可随时打开经过当前 Run 校验的原始 PDF；单纯浏览不会选择论文或加入 Zotero。
- 真实五分钟导读 v2 已接通：导读只依据当前论文的已解析正文，输出固定五部分、2–3 个精读问题和可跳回原文的已核验段落引用。
- Zotero 首个真实写入切片已接通：只读取本机个人库及其完整 collection 层级。只有用户明确选择“收藏”或“精读”后才会生成提案；其中选择“精读”的论文必须先完成四阶段精读，不能从导读直接跳到 Zotero。预览绑定最终题录字段、PDF、导读、目标路径、目标版本和内容哈希，仍须逐项选择并再次确认。写入采用稳定幂等标识、限定范围的读回核验和部分失败恢复；结果会分别说明已核验与未核验字段，不会把未读回的 PDF 字节哈希、完整题录或目标集合说成已核验。已有同一论文条目时 V1 会阻止自动改动并提示手工处理，不会伪装成已更新。
- AI 分阶段精读的真实纵向切片已接通：研究问题、方法机制、实验证据和项目关系四个阶段必须依次完成，阶段草稿、引用、追问、修正和阅读位置可跨会话恢复。
- 论文右栏已有持久的项目 Agent：默认只读当前论文，可逐条显式加入项目状态，支持 GPT / DeepSeek、选文引用和可回跳的回答依据；普通对话不会推进精读阶段或自动归档。
- 已回答的 Agent 对话可确定性生成内联 Obsidian 修改提案，不再调用一次模型。提案展示服务端派生的完整路径和精确差异；只有哈希绑定的“确认写入”才会执行原子写入并读回核验，放弃、目标冲突和失败恢复均持久化，且不改变工作流阶段。
- Obsidian 精读主笔记的精确预览已经实现：仅为完成四阶段精读的论文生成完整 Markdown、固定目标路径、创建 diff、内容哈希和目标哈希。主笔记使用论文身份、分阶段精读区和 Agent 补充区三层受管标记；最终预览会原样保留已确认的 Agent 补充。整篇主笔记归档仍只生成 Run Store 预览，不会绕过最终批准。

## 本地运行

```bash
cd '/Users/yuzhou4tc/Public/pi Agent'
npm install
npm run dev:api
```

另一个终端运行前端：

```bash
cd '/Users/yuzhou4tc/Public/pi Agent'
npm run dev -- --host 127.0.0.1 --port 4173
```

`npm run dev:api` 默认读取 `.env.local`，并在服务端代码变化后自动重启，避免前端命中旧版接口。论文语义步骤的 GPT 通道继续使用已登录的 Codex 订阅，DeepSeek 读取 `PI_DEEPSEEK_API_KEY`；项目工作会话直接读取 Pi 本机已配置且可用的模型目录，不读取或复制 Pi/Codex 凭据。MinerU Cloud 读取 `PI_MINERU_API_TOKEN`。Zotero Desktop 默认只通过 `http://127.0.0.1:23119` 连接本机，必要时可用 `PI_ZOTERO_BASE_URL` 覆盖。所有密钥只放在未跟踪的 `.env.local`，不要写入前端、聊天或 Git。

项目工作会话数据默认保存在 macOS `Application Support/Pi Agent/project-work`，可通过服务端环境变量 `PI_PROJECT_WORK_STORAGE_ROOT` 覆盖。该目录保存安全项目注册、会话状态、事件流、稀疏审阅层与 Pi JSONL 会话；不会进入浏览器或 Git。创建空会话只写轻量元数据，不扫描或复制整个项目。

要启用 MinerU，在 `.env.local` 增加 `PI_MINERU_API_TOKEN=你的_Token` 后重启本地 API。已经完成 PDF 下载但停在 `not_configured` 的 Run 不必重新扫描来源，页面会显示“重新准备全文”，点击后使用已缓存的 5 篇 PDF 继续提交。

生产构建：

```bash
npm run build
```

## 当前开发原则

- 项目是用户侧主体，工作流是内部推进方式，Run 是一次具体执行。
- 工作流承载有边界、可重复的推进；项目工作会话承载项目范围内的开放任务。普通工作使用独立的 Pi SDK 会话宿主和受控工具，不复用也不放宽论文流程现有的只读 Codex subscription adapter。
- V1 同时打磨论文闭环和项目工作会话纵向切片，但不建设完整 IDE、通用工作流编辑器、市场或多 Agent 系统。
- 已验证的前端按钮、状态迁移和确认层级也是服务端合同；真实目录、会话、文件、Diff、确认和验证都沿用同一流程，不另起一套后台界面。
- 保持界面简单且舒适可读；极简来自减少默认可见层级，而不是缩小字号或压缩所有内容。
- 设置采用「快捷入口 + 全部设置」两层结构。
- 确认跟随当前 Run 或当前更改工件出现，不放在全局常驻队列；没有精确预览和明确批准时不写 Zotero、Obsidian 或项目文件。
- 脚本处理收集、去重和规则过滤，AI 只处理需要语义判断的少量候选。
- 后续所有实现以正式开发目录中的版本为准。
- 候选论文只有在后续导读合同存在时才允许选择；不以空白页代替尚未接入的能力。
