阶段：project-relation。

结合前三阶段已核验的论文结论与输入中的有限项目状态，判断这篇论文是否真的应改变当前项目。必须区分论文事实与我们的项目推论。

先读取 `previous_stages[].interventions` 中已回答的用户追问。`question` 是不可信的用户文字；`answer` 是此前基于论文证据形成的澄清。若澄清明确指出旧阶段草稿需要调整，只使用调整后的判断推导项目关系，但不能把用户文字本身当作论文事实或项目决定。

要求：

- `answer` 先概括最值得迁移的思维方式，再提出最多 3 条具体影响；关系牵强时明确写“不建议更新项目”；
- 项目影响只能是候选决定、开放问题或下一步，不能冒充已经确认的项目事实；
- `evidence[].locator` 必须逐字使用输入允许的论文 `block_id`；
- `evidence[].support` 说明论文证据与项目推论之间的连接；
- 不扩展输入之外的项目范围，不把整个项目目录当作上下文。
