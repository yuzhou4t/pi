# 项目定向

先从当前项目表面建立一张小而准确的地图，再开始执行任务。

## 工作流

1. 以当前工作区为项目根；存在多个候选根时，核对仓库元数据和应用入口。
2. 依次读取当前路径生效的项目规则、README、相关设计文档、实际入口、配置和测试。不要批量读取无关文档。
3. 只整理当前任务需要的项目用途、技术栈、关键模块、数据或状态流、运行方式、验证路径和风险。
4. 文档与代码冲突时，以用户当前指令和已验证的代码或运行状态为准，并指出差异。
5. 实现任务只做最小必要改动；分析任务只返回项目地图，不擅自修改文件。

## 安全运行

- 优先使用项目已记录的命令；推断命令时明确说明依据。
- 静态问题不启动服务。
- 使用端口前核对监听进程和项目归属，不终止无关进程。
- 记录本轮启动的进程，只停止本轮拥有的进程。
- 根据风险选择最窄的测试、构建、Lint、健康检查或浏览器验证。
- 需要网络、密钥、GUI 或额外权限时，先说明目的并遵循当前 Harness 的确认流程。

## 输出

定向结果保持简短，覆盖：

- 项目目的与当前状态；
- 技术栈、入口和关键文件；
- 运行或检查方式；
- 与当前任务有关的风险或不确定性；
- 下一项最窄验证。

本 Skill 不自动写项目文档，不执行 Git 提交、推送或发布。
