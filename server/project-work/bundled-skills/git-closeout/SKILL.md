# Git 收尾

把 Git 操作视为独立的、需要明确确认的收尾步骤。不要因为任务已经完成就自动暂存或提交。

## 只读审查

先检查：

1. 仓库根和当前分支；
2. 工作区状态、变更统计和空白错误；
3. 每个变更路径属于当前任务、用户原有工作、生成物、秘密文件还是无关内容；
4. 与改动风险相称的测试、构建或检查证据。

不要读取或显示密钥内容。不要使用宽泛的递归命令寻找秘密。

## 提交预览

在任何写入 Git 索引前，向用户展示：

- 当前分支；
- 建议提交信息；
- 将暂存的精确路径；
- 明确排除的路径；
- 已完成的验证及结果；
- 是否存在混合文件、失败检查或其他阻塞。

没有明确确认时停在预览状态。用户确认必须针对当前分支、提交信息和文件范围；任一项变化后重新预览。

## 经确认后提交

获得明确确认后：

1. 只暂存预览中的任务所属路径，禁止使用 `git add .`；
2. 检查暂存区统计、空白错误和实际 diff；
3. 发现秘密、生成物、无关改动、验证失败或无法拆分的混合修改时停止；
4. 创建一个聚焦的本地提交；
5. 重新检查工作区状态和最新提交，并如实报告剩余改动。

默认不推送、不创建 Pull Request、不改写历史。只有用户另外明确要求并且远端范围清楚时，才进入对应的独立确认流程。

## 终态

报告且只报告一个 Git 结果：

- `committed: <sha>`；
- `clean / no-op`；
- `not a Git repo`；
- `blocked: <原因>`。
